# UniQuiz Offline — النسخة المصححة

هذا تطبيق ويب تقدّمي قابل للتثبيت. يعمل دون إنترنت بعد فتحه أول مرة عبر HTTPS وتنزيل المواد المطلوبة.

## ما الذي تغير؟

- تعرض كل سنة فهرس موادها، ولكل مادة حالة وزر مستقل.
- المادة غير المحمّلة تعرض **تحميل** فقط.
- المادة المحمّلة المطابقة للفهرس تعرض **فتح** و**إزالة**، ولا يظهر زر تحديث.
- المادة المحمّلة التي تغيّر ملفها أو أسئلتها تعرض **تحديث**.
- المادة الجديدة غير المحمّلة تبقى **تحميل**؛ لا تُحسب كتحديث.
- فحص التحديث يحمّل `content-manifest.json` الصغير فقط، ولا يحمّل ملف الأسئلة قبل ضغط الطالب على **تحديث**.
- كل مادة محفوظة كسجل مستقل في IndexedDB، مع بديل محدود في localStorage للمتصفحات القديمة.
- التقدم والملاحظات والكلمات وآخر موضع دراسة تُحفظ محلياً وتُزامن اختيارياً بحساب البريد الإلكتروني عبر Supabase.
- أصبح البنك يضم 3293 سؤالاً فريداً بعد حذف 765 نسخة مكررة و10 أسئلة غير صالحة. بقيت معرّفات الأسئلة التاريخية الـ4068 مرتبطة بالأسئلة الحالية، كي لا تضيع الملاحظات أو الإجابات القديمة.
- المواد نفسها لا تُرفع إلى حساب الطالب ولا تُزامن بين الأجهزة؛ ينزّل الطالب ما يحتاجه على كل جهاز.

## التشغيل والنشر

1. ارفع محتويات هذا المجلد كما هي إلى موقع HTTPS، مثل GitHub Pages.
2. لا تفتح `index.html` مباشرة باستخدام `file://`؛ متصفح الويب يمنع Service Worker وIndexedDB في هذا الوضع في بعض البيئات.
3. افتح الموقع مرة واحدة أثناء الاتصال، ثم ثبّت التطبيق من المتصفح إذا رغبت.
4. افتح السنة، ثم اضغط **تحميل** أمام المواد المطلوبة فقط.

للتجربة المحلية افتح الطرفية داخل مجلد المشروع وشغّل:

`node scripts/dev-server.mjs`

ثم افتح `http://127.0.0.1:4173/`. لا يحتاج المشروع إلى حزمة npm أو عملية build.

## إعداد المزامنة بحساب البريد

1. افتح Supabase Dashboard ثم SQL Editor.
2. نفّذ محتوى `SUPABASE_SETUP.sql` مرة واحدة.
3. فعّل Email ضمن Authentication > Providers.
4. أضف رابط الموقع المنشور إلى Authentication > URL Configuration.
5. افتح التطبيق واضغط أيقونة السحابة، ثم أنشئ حساباً أو سجّل الدخول.

المفتاح الموجود في الواجهة **Publishable key** وليس مفتاحاً سرياً. لا تضف `service_role` أو أي مفتاح سري إلى ملفات الموقع. سياسات RLS في ملف SQL تقصر كل صف على صاحبه.

المزامنة تستخدم مقارنة مشروطة لقيمة `updated_at` وتعيد المحاولة عند وجود كتابة متزامنة من جهاز آخر. تُدمج إجابات الأسئلة منفردة بحسب وقت تعديلها، ويُعاد الدمج إذا تغيّرت البيانات أثناء انتظار الشبكة. كما تفصل النسخة المحلية لكل حساب وتتحقق من الحساب بعد كل طلب، كي لا تنتقل بيانات مستخدم إلى حساب آخر على الجهاز نفسه.

## إضافة مادة أو تحديث أسئلة

1. ضع ملف JSON داخل مجلد السنة الصحيح.
2. حافظ على `id` لكل سؤال موجود. لا تغيّر المعرف عند تصحيح النص أو إعادة ترتيب السؤال.
3. للأسئلة الجديدة يمكنك ترك `id` فارغاً ثم تشغيل:

   `node scripts/normalize-content.mjs`

4. أعد بناء الفهرس:

   `node scripts/build-content-manifest.mjs`

5. ارفع ملف المادة و`content-manifest.json` معاً.

إذا كنت تنقل بنك أسئلة من إصدار قديم غيّر معرّفات الأسئلة تلقائياً، استورد
معرّفات التوافق **قبل** بناء الفهرس:

`node scripts/import-legacy-aliases.mjs --source "مسار-المشروع-القديم"`

يضيف الأمر `legacyIds` و`legacyPrimaryIds` ولا يغيّر المعرّف الحالي؛ وبذلك تنتقل الإجابات
والملاحظات القديمة، بما فيها معرّفات الأسئلة المكررة ذات اللاحقة `__2`.

سير GitHub Actions المرفق ينفذ الخطوتين 3 و4 تلقائياً عند رفع ملفات مواد إلى فرع `main`، ثم يحفظ التغييرات. يجب أن تكون Workflow permissions مضبوطة على القراءة والكتابة.

صيغة المادة المتوقعة:

```json
{
  "subject": "اسم المادة",
  "description": "وصف مختصر",
  "lang": "en",
  "questions": [
    {
      "id": "q_stable_unique_id",
      "q": "Question text",
      "options": ["A", "B", "C", "D"],
      "correct": 0,
      "feedback": "Optional explanation"
    }
  ]
}
```

## ضمانات التحديث

- يقارن التطبيق SHA-256 لكل مادة بالفهرس.
- يفحص SHA-256 وبنية JSON ومعرّفات الأسئلة قبل الحفظ.
- إذا انقطع الاتصال أو فشل التحقق، تبقى النسخة القديمة للمادة قابلة للعمل.
- اختفاء مادة من الفهرس لا يحذف النسخة الموجودة على جهاز الطالب؛ الحذف يدوي فقط.
- تحديث App shell يتم بواسطة إصدار جديد من Service Worker، ولا يكتب ملفات إصدار جديد داخل كاش الإصدار النشط واحداً تلو الآخر.

عند تعديل HTML أو CSS أو JavaScript ارفع رقم `APP_VERSION` في
`service-worker.js` ونسخة `?v=` في `index.html`. لا يلزم ذلك عند تحديث ملفات
المواد والفهرس فقط.

## الاختبار

شغّل:

`node tests/smoke-runtime.mjs`

ثم شغّل فحص جودة بنك الأسئلة واختبار انتقال المعرّفات:

`node tests/question-bank-quality.mjs`

`node tests/question-id-migration.mjs`

تتحقق الاختبارات من تحميل JavaScript، وحالات Download/Current/Update، وبديل التخزين المحلي، ودمج التقدم، وتطابق الفهرس مع 20 مادة و3293 سؤالاً فريداً، وعدم وجود سؤال أو خيار مكرر، وصحة حدود الإجابات، واستمرار انتقال معرّفات الأسئلة التاريخية.

## ملاحظة أكاديمية

خضع البنك لمراجعة التكرارات والتعارضات والإجابات المشتبه بها بالرجوع إلى نصوص أصلية ومصادر أكاديمية ورسمية. راجع `QUESTION_REVIEW_AR.md` والتقارير التفصيلية داخل `docs/question-review/`. تبقى مراجعة مدرس المادة هي المرجع النهائي في المسائل التفسيرية الخاصة بالمنهج.
